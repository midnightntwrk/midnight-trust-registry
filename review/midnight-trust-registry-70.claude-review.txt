## Issues

### 1. `setup-node` version comment is wrong — says `# v4`, SHA is v6.5.0 (correctness / auditability)
`.github/workflows/ci.yaml` and `.github/workflows/quality.yaml` both pin:
```yaml
uses: actions/setup-node@249970729cb0ef3589644e2896645e5dc5ba9c38 # v4
```
That SHA is **v6.5.0** (`v6` tag head), not v4. The human-readable version comment is the whole point of a pinned SHA — it's what a reviewer audits against, since the SHA is opaque. In a PR whose entire purpose is pinning hygiene, this mismatch is exactly what shouldn't ship. (The pre-existing comments were also wrong — old `2028fbc5` was v6.0.0 labeled `@v4` — so this is inherited, but this is the pass that should correct it.) **Fix the comment to `# v6.5.0`.** Also worth a conscious decision: jumping the whole toolchain from v6.0.0/v6.4.0 to v6.5.0 is fine, but do it deliberately rather than under a `v4` label.

### 2. Dependabot globally ignores *all* major updates, including `@midnight-ntwrk/*` (policy — confirm intent)
```yaml
ignore:
  - dependency-name: "*"
    update-types: ["version-update:semver-major"]
  - dependency-name: "@midnight-ntwrk/*"
    update-types: ["version-update:semver-major"]
```
Suppressing all majors is a legitimate stability choice, but note the side effect: **Dependabot security PRs that can only be satisfied by a major-version bump will not be raised.** For a repo being hardened for public exposure, that's a meaningful gap. Confirm this is intended, and consider relying on the separate Scorecard/scan coverage to catch what this hides. (The second `@midnight-ntwrk/*` entry is also redundant — the `"*"` rule already covers it.)

### 3. `scan.yaml` concurrency simplification dropped `merge_group` handling (low — likely fine)
```yaml
group: ${{ github.workflow }}-${{ github.head_ref || github.ref_name }}
```
The old expression special-cased `merge_group` events. `scan.yaml` has no `merge_group` trigger, so the removed branch was dead code and this is a safe simplification — flagging only so it's a conscious call if a merge queue is added later.
